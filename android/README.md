# PyMoney 安卓版

原来那个在 Termux 里跑命令行的记账程序（`money.py` + `functions.py` + `tools.py`）的原生安卓版。
表结构、金额单位、税负和 CPI 的算法都照搬旧程序，所以十几年积累的老 `money.db` 导进来就能直接用。

产物：`/home/code/PyMoney/PyMoney-v2.0.apk`（271 KB，versionCode 9，release 签名，v2+v3；签名证书与 1.0~1.4 相同，可直接覆盖安装，数据不丢）

## 修订记录

- **2.0（2026-11-03）**：① **解锁对话框点「取消」不再退出 App**。原来 `LockGate` 的
  negative 按钮直接 `activity.finish()`，而那个框是挂在首页上的，把首页关掉就等于退出程序。
  现在默认取消只关对话框、人还停在点击前的页面（首页可以再点一次）；
  只有桌面小组件拉起来的「记一笔」用 `ensureOrFinish`，取消时关掉那一页回桌面。
  按钮文案也从「返回」改成「取消」；② **撤掉两处调试面板**：安全页的「最近操作」卡片
  （含崩溃原文、上次备份播报）整块删除，数据页的「最近几次备份结果」列表删除，
  「上次备份」那行压缩成 `上次备份 11-03 05:46 ✅ 12880 条记录`（失败时带原因）——
  `BackupLog` 的底层记录仍在写，开加密前的「必须先有校验过的备份」和失败原因对话框还靠它；
  `PyMoneyApp` 的崩溃采集仍写私有目录 `crash.txt`，只是不再显示在界面上；
  ③ 版本号升到 **2.0**（versionCode 9）。
  ④ **空口令点「解锁」不再崩**：一个字符都不输就点「解锁」时，PBKDF2 会拿空口令去
  `SecretKeySpec`，抛 `IllegalArgumentException: Empty key`，异常穿出对话框把进程带走——
  这就是「点什么都没有、App 直接退出」。现在三层都堵上：`LockGate` 遇到空输入直接重开对话框
  （提示「还没输入口令，再试一次」），`KeyEnvelope.unlock/unlockRecovery` 对 null/空串早返回 null，
  `CryptoState` 再兜一层 catch；表现和输错口令完全一致，取消照旧回原页面。
  （开启加密时本来就不许设空口令，所以库里的口令绝不可能是空串，空输入只可能是手滑。）
- **1.4（2026-11-03）**：① 修「自选文件夹」备份的 `IllegalArgumentException: Invalid URI`：
  `Storage.saveViaTree` 把两段式的树 URI（`tree/primary:Download%2Fmoneyapp`）当成文档 URI 去调
  `DocumentsContract.getDocumentId`，而那个接口只认四段式 `tree/<id>/document/<id>`。改成先
  `getTreeDocumentId(treeUri)` 再用 `buildDocumentUriUsingTree` 拼出树根目录句柄，
  备份才真正写进你选的那个目录（「另存为」那条路一直通，所以它能成功）；②「导出明文」
  不再固定往 `Download/PyMoney` 写，改成走系统「另存为」，位置和文件名都由你自己挑；
  ③ 口令框改成默认掩码：只设 `TYPE_TEXT_VARIATION_PASSWORD` 时澎湃OS 会按系统里的「显示密码」
  把输入直接回显成明文，现在显式装 `PasswordTransformationMethod`，并在框下面加一个
  「显示口令」勾选框（默认不勾，想核对时自己勾）；解锁/恢复码那个对话框一样处理；
  ④ 深色模式：新增 `values-night` 整套配色（背景、卡片、分隔线、收支数字、提示文字，
  连自绘的坐标轴/网格/图例/饼图中心和「存到相册」导出的图都跟着换），夜间主题父样式换成
  `Theme.Material`；首页新增第 10 个入口「外观」，三选一——跟随系统 / 始终浅色 / 始终深色
  （`UiModeManager.setApplicationNightMode`，Android 12 及以上；更老的系统只提供「跟随系统」）。

- **1.3.2（2026-11-03）**：**找到并修掉了那个真正的元凶**——`BackupManager` 的构造里写的是
  `new Handler(new HandlerThread("backup").getLooper())`，而 `HandlerThread` 在 `start()` 之前
  `getLooper()` 返回 null，`new Handler(null)` 就是在 `looper.mQueue` 上抛
  `NullPointerException`。也就是说**从 1.2 起备份一次都没真正跑过**：点「立即备份」、点「导出明文」、
  甚至记完一笔（`AppDb.changed()` 会顺手触发自动备份）都在构造那一步炸掉，
  账已经提交成功了所以数据没丢，但界面直接闪回主界面、什么提示都没有——
  1.2 那条「备份的数据库文件貌似没有成功」和 1.3 那条「选确定就回到主界面」是同一个 bug。
  改成先 `start()` 再取 Looper（`SearchActivity` 一直是这么写的，所以只有备份这条路上有）。
  另外按你的要求：**「自选文件夹」不再自作主张套一层 `PyMoney` 子目录**，
  选 `Download/moneyapp` 就直接把 `money.db` 写进 `Download/moneyapp/`，
  屏幕上显示的位置、`cp` 命令里该写的路径都是那一个（默认那条路仍然是 `Download/PyMoney/`，没动）。
- **1.3.1（2026-11-03）**：把「点了没反应」变成屏幕上的一句话。上一版真机反馈：选了「我自己选一个文件夹」没生效、备份说失败但目录里什么都没多、点「开启加密 → 确定」直接闪回主界面且无任何提示。构建机看不到手机，所以这一版做的是**让失败自己把原因说出来**：① `Storage.saveDownload` 不再赌一条路，依次试「覆写自有行 → 带 `IS_PENDING` 新建 → 不带的新建」× 「`MediaStore.Downloads` 集合 → `MediaStore.Files` 集合」，每条路的异常都攒起来一并报，界面上能看到具体哪一步、什么异常类；② 写完的回读改成 `readBackAfterWrite`：按 uri 和按「目录 + 文件名」两种句柄各试三次、间隔 300 ms，媒体库索引慢半拍不再被误判成失败；③ 名字被媒体库顶成 `money.db (1)` 时，路径后面直接跟一句原因（目录里已有一份同名文件不是本应用创建的，多半是卸载重装留下的；`cp money.db` 拿到的仍是旧那份）；④ 新增 `PyMoneyApp` 捕获未处理异常写进私有目录 `files/crash.txt`，下次进「安全与加密」页时把崩溃原文显示在「最近操作」里——闪退从此有据可查；⑤ 安全页新增「最近操作」卡片，备份中/成功/失败、上次备份结果、崩溃原因都往这里落，不只弹 toast（通知被静音或被系统限制时 toast 可能整个不出现）；开启加密那一步的备份失败时，当场给一个「改用系统另存为」的对话框，写完照样回读校验，校验通过同样能满足「开启加密前要先有备份」那道门；⑥ 数据页选完目录位置立刻在屏幕上显示生效后的位置；拿不到持久授权（`SecurityException`）或保存框没交回目录时，屏幕留下原因并给「换用每次都问我 / 再试一次」两个选择；备份失败同样自动弹「改用另存为」；⑦ 明文状态下把「口令」那张卡整块藏掉，不再摆四个必然灰着的按钮。
- **1.3（2026-11-03）**：列级加密（只加密文字）+ 新增「安全与加密」页。① `Income.Name` 与 `IncomeType.TypeName` 存成 `enc:v1:<base64(iv‖密文‖tag)>`，AES-256-GCM、AAD 绑列名；**时间/金额/类型 ID 保持明文**，所以全部 SQL 聚合、图表、税负、CPI 在加密后逐值不变（对拍体系没死，见「验证」）；② 密钥是纯口令方案：随机 DEK 干活，`PBKDF2-HMAC-SHA256(口令, salt, 120000)` 派生 KEK 把 DEK 包住，信封存进新建的 `AppCrypto(k,v)` 表（只加新表，`Income`/`IncomeType` 一个列都没动），口令本身以任何形式都不落盘，杀掉进程就得重输；③ `core/CryptoState` 是「这库加密了吗、现在解开了没」的唯一权威，明文/已加密未解锁/已解锁三种状态之间切换不会崩，库里跑一半是混合态也照常能用；④ `db/Migrator` 负责搬那一万两千行：先在私有目录留明文退路 → 类别名先迁 → 事项名 500 条一个事务、批末记游标可续跑 → 迁完自证（指纹逐字段不变 + 抽 500 条能原样解回）；反向 `toPlain()` 可整个退回明文；⑤ 需要明文的功能页进门过 `ui/LockGate`，安全页本身锁着也进得去；⑥ 备份位置与明文导出分开：日常备份写 `money.db`（加密后就是密文库），「导出明文」写 `money-plain.db`，两者不再互相顶掉；⑦ 查账页的关键字搜索移到后台线程 + 250ms 防抖（加密后关键字只能在解密后于内存里筛，留在主线程就是 ANR）。
- **1.2（2026-11-03）**：备份从「拼字符串报成功」改成「写完回读、打开、比指纹」。① 新增 `db/Fingerprint`（条数/maxID/最早最晚时间/金额合计/类别数）与 `core/BackupLog`（最近 8 次结果存在设置里，数据页直接显示）；② 备份位置可选三种——默认 `Download/PyMoney`、自己选的文件夹（SAF 持久授权，记住）、每次问我；③ 写公共目录时先原地覆写（`openOutputStream` 的 `"wt"`）而不是删了重建，`money.db (1)` 那种带序号的第二份从此不会产生，删旧行的分支限定在 `DISPLAY_NAME + RELATIVE_PATH + OWNER_PACKAGE_NAME`，不再可能碰到别处的同名文件；④ `VACUUM INTO` 快照、写文件、回读校验全部移到后台线程，主线程不再做磁盘活；⑤ 导出 CSV 改为系统「另存为」，可以自己挑位置和文件名；⑥ 数据页新增「导出明文 money.db（给 Termux 覆盖用）」和那条 `cp` 命令原文，并写清 App 库与 Termux 库是两个文件。

## 构建

```bash
cd /home/code/PyMoney/android
./build-manual.sh                      # 默认按 manifest 里的 versionName 产出 ../PyMoney-v2.0.apk
./build-manual.sh PyMoney-v2.0.apk     # 换输出名
```

这台机器只有 1 核、约 535 MB 可用内存，Gradle + AGP 会被内存打死，所以走手工链，
效果一样且不需要联网下载依赖：

1. `aapt2 compile --dir res` → `aapt2 link`（顺带 `--java` 生成 `R.java`）
2. `javac -source 8 -target 8 -bootclasspath android.jar`
   —— 代码里刻意不写 lambda（android.jar 的 `LambdaMetafactory` 是空壳，javac 会报
   `Unable to find method metafactory`），全部用匿名内部类
3. `d8 --release --min-api 24` 出 `classes.dex`
4. 用 python 的 `zipfile` 把 `classes.dex` 塞进 aapt2 产出的 apk（机器上没有 `zip` 命令）
5. `zipalign -f 4` → `apksigner sign`（minSdk 24，apksigner 自动只签 v2+v3）

依赖：JDK 17、`/opt/android-sdk` 下的 `platforms/android-35` 和 `build-tools/35.0.0`。
可用环境变量覆盖：`ANDROID_HOME`、`ANDROID_BUILD_TOOLS`、`ANDROID_PLATFORM`、
`PYMONEY_KS_PASS`、`PYMONEY_KS_ALIAS`、`OUT_APK`。

签名参数：别名 `pymoney`，口令 `pymoney`（脚本里默认值，可自行换），RSA 2048，有效期 10000 天。
证书 SHA-256 `451db9489eaabd74c63e57e35593af3a8a567d5ebc0d76a4e754e4d7884c3322`。

> **`pymoney.jks` 务必备份到别处。** 以后想覆盖安装（`adb install -r` 或直接在手机上升级），
> 必须用同一个 keystore 签名；丢了就只能先卸载旧包再装新包，而卸载会把 App 私有目录里的库删掉。

## 验证（本机跑不了模拟器，也没有 KVM，所以核心层在 JVM 上对拍）

```bash
cd /home/code/PyMoney/android
./harness/run.sh            # 默认用 ../money.db，写入自检在临时副本上做，不动真库
./harness/run.sh --crypto   # 再加一遍加密、迁移、跨实现（Python 独立解 Java 的密文）
```

最近一次全绿的实际输出（2026-11-03，12877 条真库的副本上跑）：

```

图表校验：36 项合计一致，36 个图种有数据
备份自检：4 项通过（12877,12924,20111018,20261102,49839737,64）
加密自检：72 项通过（Java 侧）
跨实现校验：35 项一致（Python 与 Java 互解）
迁移自检：47 项通过，库已迁成密文（12941 条）
加密库对拍：698 个数值与明文库零差异（税负、CPI 都算进去了）
加密库图表：74 行与明文库一致
Python 解密后参照：698 个数值与原始明文库零差异

```

`--crypto` 里最值得盯的三条：

- **加密库对拍 == 明文库对拍**：把同一套 698 个数值在密文库上再算一遍逐字符 diff。
  这条成立的前提就是「只加密文字、时间/金额/类型 ID 不动」，它是整个方案没把数字搞坏的直接证据。
  税负和 CPI 尤其要看这一条：`calc/Tax.java` 里硬编码了 50 多个中文类别名，
  类别名一旦加密，`idByName` 匹配不上就会把税负算成 0——所以 `TypeDao` 走解密缓存，
  而这两页进门必过 `LockGate`。
- **跨实现校验**：Java 写的密文交给 Python 的 `hashlib.pbkdf2_hmac` + `cryptography.AESGCM`
  独立解（`harness/crypto_crosscheck.py`、`harness/py_decrypt.py`），
  解出来的库再拿原参照程序跑一遍 698 个数值。两边真能互通，格式里就没有私有暗坑。
- **迁移自检 47 项**：正向迁完指纹逐字段不变 + 12877 条逐条解密等于原文 + CSV 逐字节相同；
  在第 13 批处人为抛异常打断，验游标停在批尾、混合态照样能读、续跑能跑干净；
  反向 `toPlain()` 退回的库和最初明文库指纹、CSV 全同（可逆性）；
  锁着的时候拒绝回退、拒绝写入、读出来全是掩码；
  「导出明文」那条路径单独验：没钥匙拒绝导出、就地解开的条数对得上、
  解出来的库指纹/逐条原文/CSV 与原始明文库相同、`AppCrypto` 已清空。

`harness/src/com/pymoney/harness/Compare.java`：拿 `sqlite-jdbc` 直接跑 App 的核心层，
  把 4 个时间段 × 全部类型合计、税负 11 项分项与税负率、年度/月度分桶、CPI 逐年与年均
  几何平均等，按 `%.6f` 打印
- `harness/py_reference.py`：直接 `import` 原程序的 `tools.py` / `functions.py`
  （以及 `scipy.stats.gmean`）算同一批量
- 两者逐字符 diff：**698 个数值零差异**
- 另有 26 项写入路径自检（增删改、按类型合计跟随改名、元↔分换算、闰年与月末、空区间税负、
  无数据年份 CPI）全部 PASS
- `ChartCheck.java` 把 9 种图的数据组装跑一遍，校验「图上画出来的合计 == SQL 直接算的合计」、
  排行确实降序、Top20 不超 20 项、无 NaN/Inf：**36 项合计一致**（12877 条、182 个月、16 个年份）

税负和 CPI 的公式**一个字都没改**，包括原程序里按「分」和按「元」混着算的地方——改了就和不上历史数字。
唯一刻意修掉的是旧 `tools.py` 里 `int(x * 100.0)` 的截断（0.07 元会被存成 6 分），
新录入的金额用 `BigDecimal` 半进位换算；老数据不受影响。

- **「备份成功」现在是有证据的**：写完之后会把那个文件重新读回来、以只读方式打开、

  那个路径还是字符串拼的，所以成没成根本不可知。
- **备份位置三种**（数据页 → 更改…）：

## 加密（1.3）

菜单第 9 项「安全与加密」。开关、口令、恢复码、明文副本都在这页，锁着也进得去（否则改不了口令）。

**加密了什么**：`Income.Name`（事项名）和 `IncomeType.TypeName`（类别名），存成
`enc:v1:<base64(12字节iv ‖ 密文 ‖ 16字节tag)>`，AES-256-GCM，AAD 绑列名（把 Name 的密文
搬到 TypeName 上解不开）。**时间、金额、类型 ID 保持明文**——这是刻意的取舍：保住全部
SQL 聚合、9 种图表、税负、CPI 逐值不变，也保住旧程序的 schema 兼容（没加列、没改列类型）。

**它防得住**：文件被拷走或手机被捡到后直接打开看明文；`Download/PyMoney/` 里那份备份被别的
App 或别人读到；用 `sqlite3` 之类的工具静态翻账本内容。
**防不住**：内存里的明文与密钥（root / frida）、正在使用时库里时间金额类型 ID 全透明、
密文长度暴露明文长度、每条记录的出现次数与时间间隔、截屏 / 通知 / 剪贴板。
要的是「不通过 App 看不到明文」，不是「对抗有 root 的攻击者」。

**口令模型（纯口令，没有 AndroidKeyStore）**：
随机 32 字节 DEK 真正干活；`PBKDF2-HMAC-SHA256(口令, 16字节salt, 120000 轮)` 派生 KEK 把 DEK
包住；信封（salt / 轮数 / wrappedDEK / verifier）写在库内新建的 `AppCrypto(k,v)` 表里，
所以备份文件自描述，换机或清除数据后导入备份仍能凭口令解开。
DEK 只在内存，进程被杀就没了，**口令以任何形式都不落盘**（不进 SharedPreferences、不进日志）。
改口令只重新 wrap 一次 DEK，不重算数据；**恢复码同样只是另一把 wrap**，所以口令忘了还能补、
也能事后新增或换恢复码，不会把库变成砖。

**开加密的三道门**（安全页会按顺序带你走）：
1. 必须已有一次「回读校验通过」的备份（`BackupLog.hasVerified`），没有就先给你去备份；
2. 设口令（两次输入一致，至少 6 位）；
3. 二选一：抄下一次性恢复码（16 位、去掉易混字符，建议另存到别处），或者明确勾选
   「我不需要恢复码」。**忘记口令又没有恢复码 = 数据永久不可读，没有任何后门。**

**开启之后**：
- 每次启动（进程被杀重进）都要输口令。首页本月概览和桌面小组件不需要明文，不进那道门；
  查账、记一笔、编辑、类型管理、图表、税负、CPI、导出 CSV/备份/导出明文、状态页分类明细
  进门先要口令（`ui/LockGate`）。
- 数据页有「立即锁定」，清掉内存里的 DEK；锁着时列表读出来是 `🔒 已加密`，写入被拒绝，
  不会出现半截掩码存进库。
- 迁移（一次改 12877 行）在后台线程跑，带进度条，手机预估 2~8 秒。中途被系统杀掉不算坏事：
  游标记在 `AppCrypto`，重进能续跑，混合态下 App 照常可用（已迁的解得开、没迁的还是明文）。
- 私有目录会留一份明文退路 `money.db.plain`（迁移是唯一一次大规模 UPDATE，没有退路就是拿
  十几年的账赌 SQLite 不出错）。它和加密目的对冲，所以只留 **7 天**自动删，安全页显示它的
  存在与天数，并提供「现在就删」「删之前先导出」。
- 加密库仍是合法的 money.db：`SELECT * FROM Income` 照旧能读，旧程序不会崩，只是文字是密文。
  真要在 Termux 里读明文，用「导出明文」那条路径。

**App 之外的后备读数**（`android/tools/pymoney_dump.py`）：算法是公开的，信封就在库里，
所以口令在手就不必依赖 App 才能看账——App 哪天装不上、仓库不再维护，账本也不至于变砖。
它同时也是跨实现自检的第三次印证（前两次是 `crypto_crosscheck.py` 和 `py_decrypt.py`）。

```bash
pkg install python-cryptography
python3 pymoney_dump.py money.db --sum                    # 条数/范围/收支合计，先确认口令对
python3 pymoney_dump.py money.db -o out.csv                # 解成 CSV（Time,Name,Amount,TypeName）
python3 pymoney_dump.py money.db --plain plain.db          # 还原一份明文库给老程序直接用
PYMONEY_PASS=口令 python3 pymoney_dump.py money.db --list  # 非交互场合；口令走环境变量不走 argv
```

以 `RECOV-` 开头的串会自动当恢复码用。脚本对库只读打开；`--plain` 是复制一份再就地解，
解不开任何一条就整体失败、不留半截文件。在 12877 条的加密副本上实测：
`--sum` 给出 `12877 条 / 20111018~20261102 / 收入 1628755.85 / 支出 -1130358.48 / 结余 498397.37 / 64 类`，
与 App 指纹 `12877,12924,20111018,20261102,49839737,64` 一致；
它导出的 CSV 与同一批数据在明文库上导出的 **12878 行、448964 字节逐字节相同**。

## 已知限制

- 构建机上没有模拟器也没有真机，**UI 我一次都没点过**。数字、SQL、图的数据都对拍过了，
  但布局遮挡、字号、滚动这类只能你装上后反馈再调。加密那条链尤其如此：迁移真实耗时、
  被系统杀进程后的续跑、要口令的时机、锁定后哪些页面还看得懂，只有真机说了准。
- 这是**应用层的列级加密**，不是全盘加密。它保证「不通过 App 看不到明文」，
  防不住 root / frida 读内存，也不掩盖时间、金额、类型 ID、条数与记账间隔。见上节。
- 忘记口令又没有恢复码 → 全库永久不可读，**没有后门**，谁都救不回来。这是设计如此。
- 加密后 `Download/PyMoney/money.db` 是密文库，老程序读不了它的文字；Termux 那边要用
  「导出明文 money-plain.db」，或者 `tools/pymoney_dump.py`。
- 明文退路 `money.db.plain` 与加密本身对冲，所以限 7 天、放私有目录；迁移没确认成功前别手删。
- 图表自绘只做了 5 个基础视图（柱/折线/堆叠/横条/环形），动效、手势缩放没有；
  明暗倒是有两套（1.4 起），但每一套是静态配色，不随系统「动态取色」变。
- 明暗的「只改这个 App」用的是 `UiModeManager.setApplicationNightMode`，**Android 12 起才有**；
  更低版本只能跟随系统。桌面小组件由宿主（桌面）的资源环境决定，可能和 App 里选的不一致。
- `targetSdk 34` 而不是 35，是为了避开 Android 15/16 强制 edge-to-edge 带来的一整套 insets 改造。
- 卸载或「清除数据」会连库一起没，靠 `Download/PyMoney/money.db` 那份备份兜底
  （加密后要凭口令解，见「加密（1.3）」）。
- 小组件点下去是打开「记一笔」，不能像某些付费 App 那样在桌面上直接输入完成记账
  （AppWidget 的输入限制，得进 Activity）。
